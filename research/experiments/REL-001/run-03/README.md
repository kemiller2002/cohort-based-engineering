## Running

### Without an agent (harness checks)

```sh
python3 -I fixtures/check-static.py fixtures [RUN02_FIXTURES]   # S1–S8, no .NET
REL003_DOTNET_ROOT=… fixtures/check.sh                          # full fixture proof (~10 min)
REL003_DRY_RUN=1 harness/smoke.sh                               # setup → stand-in agent → score; no .NET, oracle skipped
REL003_DOTNET_ROOT=… harness/smoke.sh                           # same, with the hidden oracle scored (arms A/B)
python3 -I analysis/selftest.py                                 # analysis determinism and X2/X3/X4 handling
REL003_CACHE_CONDITION="K1 isolated-cli" harness/trial.sh start bare V2 REL-001-R3-SMOKE-V2-r1-bare-x \
  && harness/trial.sh launch REL-001-R3-SMOKE-V2-r1-bare-x --print-only   # the exact K1 command; starts nothing
```

Smoke runs need run ids that contain `-SMOKE-`. They stay in the harness state and never become
observations. The arm C and D smoke cases need the Echelon binaries (`REL003_PRAXIS_C/D`,
`REL003_DOKIMOS_C/D`, `REL003_ORDO_C/D`).

### Pilot, then trials (after G1, G2 and G4–G8)

For each entry in `pilot-order.json`, then in `order.json`, one at a time:
- **K1:**

  ```sh
  harness/trial.sh start ARM TASK RUNID
  harness/trial.sh launch RUNID
  ```

- **K0:**

  ```sh
  harness/trial.sh start ARM TASK RUNID
  ```

  Then run one Agent-tool sub-agent with the wrapper prompt, and finish:

  ```sh
  harness/trial.sh finish RUNID TRANSCRIPT_DIR AGENT_ID[:TOKENS:USES:MS]
  ```

After the pilot, record G3 and the P1 cache decision as a dated amendment, then run the confirmatory order.
Finally:

```sh
python3 -I analysis/analyze.py    # → analysis/results.json
```
